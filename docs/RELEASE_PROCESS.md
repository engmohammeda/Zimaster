#  عملية الإصدار الاحترافية — Z-Mastery

> سير العمل `.github/workflows/android-release.yml` (نسخة 2026‑08‑26):
> وظيفتان — **CI** للفحص السريع على أي فرع/PR، و**Release** للنشر الكامل على
> main/الوسوم/التشغيل اليدوي. لا أسرار في الكود إطلاقاً.

---

## 1) ماذا يحدث تلقائياً في كل Release؟

1. **اختبارات إلزامية** `:app:testDebugUnitTest` — فشلها يوقف النشر (بوابة جودة).
2. **ترقيم semver تلقائي** من آخر وسم إصدار:
   - وجود `feat:` بين الـ commits ← رفع **minor** وتصفير patch.
   - وإلا ← رفع **patch**.
   - الرقم يُختم في `versionName` داخل البناء نفسه (يظهر على الجهاز).
3. **ملاحظات مصنّفة تلقائياً** من الـ commits منذ آخر إصدار:
   | البادئة | القسم |
   |---------|-------|
   | `feat:` | ✨ أُضيف |
   | `fix:` | 🐛 أُصلح |
   | `refactor:` `perf:` `style:` | 🛠 تغيّر |
   | `ci:` `chore:` `build:` `docs:` | ⚙️ داخلي |
   > التزام الفريق بـ Conventional Commits هو ما يجعل الملاحظات صادقة —
   > كل commit يبدأ ببادئة صحيحة.
4. **بصمات SHA256** لكل ملف تُذيل الملاحظات.
5. **GitHub Release** بعنوان `Z-Mastery vX.Y.Z (Build #N)` ووسم `vX.Y.Z-build.N`
   (الوسم لا يطابق صيغة semver الصارمة فلا يدخل في حساب النسخة التالية ولا يسبب حلقات).
6. **تلجرام** (إن ضُبط السرّان): رسالة نصية بالملاحظات كاملة، ثم Debug APK ثم
   Release APK ثم AAB كملفات. غياب السرّين = تحذير وتخطٍّ، لا كسر للإصدار.

## 2) ضبط تلجرام (مرة واحدة)

1. في تلجرام: **BotFather** ← `/newbot` ← اختر اسماً ← انسخ الـ **token**.
2. أنشئ قناتك/مجموعتك وأضف البوت إليها **بصلاحية إرسال**.
3. احصل على Chat ID:
   - قناة: افتح `https://api.telegram.org/bot<TOKEN>/getUpdates` بعد نشر أي شيء،
     أو استخدم `@userinfobot`/`@getmyid_bot` للحساب الشخصي؛ معرف القناة يبدأ بـ `-100…`.
4. GitHub ← المستودع ← **Settings → Secrets and variables → Actions → New repository secret**:
   - `TELEGRAM_BOT_TOKEN` = التوكن
   - `TELEGRAM_CHAT_ID` = المعرف
5. **أبطل أي توكن قديم** سبق تسريبه (تدقيق 08‑25) — لا تعد استخدامه أبداً.

## 3) أسرار أخرى يدعمها السير (اختيارية)

| السر | الغرض |
|------|-------|
| `GOOGLE_SERVICES_JSON` | base64 لملف Firebase الحقيقي — بدونه يستخدم CI بديلاً مؤقتاً |
| `KEYSTORE_BASE64` + `KEYSTORE_PASSWORD` + `KEY_ALIAS` + `KEY_PASSWORD` | توقيع Release حقيقي لـ Play |

## 4) وظيفة CI (غير Release)

على كل دفعة لفرع غير main وكل Pull Request: بناء Debug + الاختبارات، ورفع
APK فحص كأثر (7 أيام) — بلا Release ولا تلجرام، فتبقى قناة الإصدارات نظيفة.

## 5) كيف أكتب commit جيداً؟

```
feat: شاشة الأهداف التطبيقية — قصة اليوم نحو هدف المتعلم
fix: مهلة 25ث لعمليات Firestore حتى لا تعلق الأزرار
refactor: توحيد معرّف مستند الدرس بين النشر والسكربت
ci: بوابة اختبارات إلزامية قبل النشر
```

سطر أول ≤ 70 حرفاً بالبادئة الصحيحة؛ التفاصيل في جسم الـ commit إن لزم.
