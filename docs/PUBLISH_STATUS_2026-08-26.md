## 1) ملخص تنفيذي

| المحور | قبل | بعد |
|--------|-----|-----|
| هل الدرس مرفوع؟ | لا يوجد أي مؤشر — لا في الشاشة ولا في البيانات | حقل `publishedAtMillis` + `publishedDocId` لكل درس، شارة لكل درس ولكل كورس، وعدّاد عام |
| رسالة فشل النشر | نص خام `PERMISSION_DENIED…` **بلون أخضر** (يبدو نجاحاً) | سطر نتيجة موحّد: أخضر = نجاح، أحمر = فشل + السبب + الحل |
| سبب رفض السحابة | مجهول تماماً | بطاقة «تشخيص الاتصال والنشر» + زر فحص حيّ (كتابة تجريبية ثم حذفها) |
| نشر كل الدروس | يقول «تم النشر» حتى لو فشل رفع **كل** الدروس | يعطي العدد الحقيقي للنجاح/الفشل + أول خطأ مترجماً |
| وضع المطور | يضيع بعد كل إعادة تشغيل (لم يكن محفوظاً) | محفوظ في الحالة (`developerUnlocked`) |
| إغلاق الإعلان | يعود للظهور عند كل إقلاع | محفوظ (`dismissedAnnouncementId`) |
| قواعد Firestore | `request.auth.token.email.matches(...)` على حساب ضيف = خطأ تقييم يُترجم كرفض غامض | فحص `!= null` قبل المقارنة |

## 2) علامة «تم الرفع»

**مصدر الحقيقة:** معرّف مستند Firestore = `{courseId}_lesson_{lessonNo}` — نفس القاعدة في
`CloudSync.publishLessonToCloud` وفي `upload_lessons.py`، ومجموعة الآن في دالة واحدة
`CloudController.lessonDocId(lesson)`.

**كيف تُملأ الشارة:**

| الطريق | متى |
|--------|-----|
| نشر درس / دفعة / «نشر الكل» | فور نجاح كتابة المستند |
| دروس وصلت من السحابة أثناء المزامنة | بالتعريف هي موجودة في السحابة |
| زر **«تحقق من السحابة»** | يقارن كل الدروس المحلية بفهرس `/lessons` الحقيقي (يشمل ما رفعه سكربت البايثون)، ويضع الشارة أو يمسحها |
| مزامنة التقدم بين جهازين | `StateMerger` يأخذ أحدث طابع زمني ولا يفقده أبداً |

**أين تظهر:**
- أعلى بطاقة النشر: شارة `مرفوع ✓` أو `x/y مرفوع` + شريط تقدم + تفصيل لكل كورس.
- شريط الحالة السريع: `دروس مرفوعة / عبارات / طلاب`.
- داخل الكورس (للمسؤول فقط): أيقونة لكل درس (`TaskAlt` أخضر = مرفوع، `CloudOff` = غير مرفوع) وسطر حالة للكورس.

> الفحص التلقائي يحدث **مرة واحدة في الجلسة** عند أول فتح للشاشة حتى لا يُنزَّل فهرس
> الدروس مع كل فتح (Firestore على أندرويد لا يدعم اختيار حقول، فيُنزَّل المستند كاملاً).

## 3) لماذا كان «بث الإعلان» لا يعمل

الأسباب الأربعة التي عولجت:

1. **لا جلسة سحابية** — `postAnnouncement` كانت تكتب بلا ضمان وجود حساب (إذا كانت
   المزامنة متوقفة لم يُنشأ حساب ضيف). الآن `ensureCloudSession()` قبل أي كتابة.
2. **صلاحية محلية ≠ صلاحية سحابية** — كود `ADMIN2026` يفتح الواجهة فقط؛ قواعد
   Firestore لا تقبل إلا حساب المالك أو دور `admin` في `/users/{uid}`. الشاشة الآن
   تعرض هذا صراحة (`isLocalOnlyAdmin`).
3. **القواعد لم تُنشر** — أي مسار غير معرّف يسقط في `deny`. زر «فحص الآن» يميّز هذه
   الحالة فوراً برسالة `PERMISSION_DENIED` مترجمة.
4. **الرسالة الخضراء** — الفشل كان يُعرض بلون النجاح، فيظن المستخدم أن الزر ميت.

```bash
# إذا قال الفحص PERMISSION_DENIED:
firebase deploy --only firestore:rules
firebase deploy --only firestore:indexes
```

## 4) الملفات المتغيّرة

| الملف | التغيير |
|-------|---------|
| `data/Models.kt` | `publishedAtMillis` / `publishedDocId` / `isPublishedToCloud` |
| `data/Persistence.kt` | نفس الحقلين في `LessonDto` + `dismissedAnnouncementId` + `developerUnlocked` في `ProfileDto` |
| `data/Mappers.kt` | تمرير الحقلين في الاتجاهين |
| `data/StateMerger.kt` | دمج شارة الرفع + الإعلان المُغلق بلا فقدان |
| `cloud/CloudSync.kt` | `fetchCloudLessonIndex` · `fetchRoleDoc` · `probePublishPermission` · تحقق من نص الإعلان |
| `viewmodel/CloudController.kt` | `lessonDocId` · `applyCloudMarks` · `verifyCloudLessons` · `probePublishPermission` · `describeCloudError` · نشر دقيق النجاح/الفشل |
| `viewmodel/AppViewModel.kt` | حالة النشر + الحفظ/الاستعادة + الواجهات العامة |
| `ui/screens/DeveloperToolsScreen.kt` | إعادة تصميم كاملة |
| `ui/screens/CourseScreen.kt` | شارة الرفع لكل درس ولكل كورس (للمسؤول) |
| `firestore.rules` | تأمين `isSuperAdminToken()` ضد الحساب الضيف |

كل حقول الحالة الجديدة **اختيارية بقيم افتراضية**، فالنسخ الاحتياطية القديمة تُقرأ بلا فقدان
(`ignoreUnknownKeys = true`).
