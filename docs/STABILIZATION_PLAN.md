## 1) التشخيص (ما وجده الفحص الكامل)

### ✅ الأساس السليم (لا يُمس)
- **استيراد JSON موحّد** (`ImportEngine` في `JsonSchema.kt`): ملف درس واحد (`metadata` + `lesson_content` + `global_vocabulary` + `lesson_notes` + `quiz`) أو حزمة متعددة الدروس.
- **25 كورساً ثابتاً** بمفاتيح مستقرة (`key` / `jsonId`) في 3 مستويات.
- **نظام مراجعة FSRS** كامل للكلمات والدروس، موافقة على الكلمات، اختبارات، نسخ احتياطي، TTS.
- **4 شاشات دروس مصقولة**: `VocabCardsLesson` · `GrammarLesson` · `ConversationLesson` · `ReadingLesson` + شاشة صوتيات خاصة.

### 🔴 الخلل الحرج #1 — فقدان البيانات بعد إعادة التشغيل
عند الاستيراد (`AppViewModel.importLesson`, سطر ~3362) تُملأ كل الحقول الغنية، لكن `LessonDto` (في `Persistence.kt`) يحفظ فقط الحقول الأساسية + `rawJson`. الحقول التالية **تضيع نهائياً عند إغلاق التطبيق**:

| الحقل المفقود | التأثير المرئي بعد إعادة التشغيل |
|---|---|
| `keyExpressions` | درس المحادثة يفقد قسم «التعبيرات المهمة» |
| `explanationAr` + `logicAr` + `examples` | درس القواعد يفقد الشرح والأمثلة |
| `fullTextEn/Ar` + `segments` | درس القراءة يفقد تقسيم الجُمل التفاعلي |
| `topicEn/Ar` + `brainstorming` + `guidedSentences` + `finalDraft` | درس الكتابة يفقد كل شيء |
| `audioReady` (للدروس) + `wordAudioReady` / `exampleAudioReady` (للكلمات) | أعلام الصوت المولّد تصفِر نفسها |

### 🔴 الخلل الحرج #2 — أنماط بدون واجهة حقيقية
`LessonScreen.kt` يوجّه 14 قيمة `LessonStyle` إلى 4 شاشات فقط؛ وما لا يُطابق يسقط في `else → GenericLesson`:
- **الكتابة (`WRITING_PRACTICE`)**: حقولها موجودة في النموذج ومليئة من الاستيراد، لكن **لا تُعرض في أي شاشة إطلاقاً** (تحققنا بالبحث: لا استخدام لـ `brainstorming/guidedSentences/finalDraft` في أي UI).
- **الاستماع (`LISTENING_AUDIO`)** و**الكوميدي (`COMEDY`)**: يقعان على الشاشة العامة الضعيفة (لا تحكم قراءة، لا صوتيات متكاملة، لا تصميم).

### 🟡 ملاحظات ثانوية
- `PhoneticsLessonScreen` تعيد تحليل `rawJson` في كل فتح (تعمل، لكنها استثناء عن النمط — ستُدمج كبلوك).
- تكرار تصاميم الأقسام بين الشاشات الأربع (Hero، مفردات، ملاحظات، اختبار) = فرصة توحيد.

## 2) التصميم المعتمد — «شاشة الدرس الموحّدة» (Block-Based)

**المبدأ:** المحتوى يقود الواجهة، وليس نوع الكورس. لا شاشة جديدة لأي كورس — اليوم أو مستقبلاً.

```
Lesson (بيانات)  ──►  LessonBlockMapper (موجّه واحد)  ──►  List<LessonBlock>  ──►  LazyColumn واحدة
```

### 2.1 البلوكات (13 بلوكاً — كلها مستخرجة من الكود الحالي المصقول)

| # | البلوك | مصدر البيانات | شرط الظهور | مأخوذ من |
|---|---|---|---|---|
| 1 | `HeroBlock` | title/no/summary + إحصاءات ديناميكية | دائماً | توحيد الـ4 Heroes |
| 2 | `VocabWordsBlock` | `newWordIds → vocab` مع `RevealMode` + صوت | كلمات > 0 | `VocabCardsLesson` (الأجمل) |
| 3 | `KeySentencesBlock` | `keySentences` | غير فارغة | `VocabCardsLesson` |
| 4 | `GrammarRuleBlock` | `explanationAr` + `logicAr` | غير فارغ | `GrammarLesson` |
| 5 | `ExamplesBlock` | `examples` | غير فارغة | `GrammarLesson` |
| 6 | `DialogueBlock` | `dialogues` + زر تشغيل الكل | غير فارغة | `ConversationLesson` |
| 7 | `KeyExpressionsBlock` | `keyExpressions` | غير فارغة | `ConversationLesson` |
| 8 | `ReadingBlock` | `segments`/`fullText` + وضعان (مقسّم/كامل) + كشف الترجمة | يوجد نص | `ReadingLesson` |
| 9 | `PhoneticsBlock` | `rawJson` عبر `PhoneticsParser` (أصوات/أزواج/تدريب) | التحليل ناجح | `PhoneticsLessonScreen` |
| 10 | `WritingBlock` 🆕 | `topicEn/Ar` + `brainstorming` (إجابات قابلة للكشف) + `guidedSentences` + `finalDraft` + مربع كتابة Draft محلي | يوجد موضوع | **جديد** |
| 11 | `NotesBlock` | `notes` / `keyPoints` | غير فارغة | موحّد (تصميم واحد) |
| 12 | `QuizBlock` | `quiz` → يفتح `lessonQuiz/{id}` | أسئلة > 0 | توحيد الـ3 QuizCards |
| 13 | `ActionsBlock` | رابط ذهني + زر الإكمال/التراجع | دائماً | من `LessonScreen` الحالي |

### 2.2 دور الكورس بعد التوحيد
الكورس يحدد **ثلاثة أشياء فقط**: اللون (`accent`) · الأيقونة · **ترتيب البلوكات**. وهذا كل ما ستبقى عليه `LessonStyle`:

```kotlin
// سياسة الترتيب — خريطة اختيارية، والافتراضي يكفي لمعظم الأنماط
val DEFAULT_ORDER = listOf(HERO, VOCAB, SENTENCES, READING, DIALOGUE,
    EXPRESSIONS, GRAMMAR, EXAMPLES, PHONETICS, WRITING, NOTES, QUIZ, ACTIONS)

val ORDER_OVERRIDES = mapOf(
    CONVERSATION  to listOf(HERO, DIALOGUE, EXPRESSIONS, VOCAB, NOTES, QUIZ, ACTIONS),
    GRAMMAR_RULES to listOf(HERO, GRAMMAR, EXAMPLES, VOCAB, NOTES, QUIZ, ACTIONS),
    READING_TEXT  to listOf(HERO, READING, VOCAB, NOTES, QUIZ, ACTIONS),
    PHONETICS_SOUNDS to listOf(HERO, PHONETICS, VOCAB, NOTES, QUIZ, ACTIONS),
    WRITING_PRACTICE to listOf(HERO, WRITING, VOCAB, NOTES, QUIZ, ACTIONS),
    // ... وكل نمط لم يُذكر يأخذ DEFAULT_ORDER
)
```

### 2.3 بنية الملفات المستهدفة
```
ui/screens/lessons/
  blocks/
    LessonBlocks.kt        ← sealed class LessonBlock + LessonBlockMapper (موجّه واحد)
    HeroBlock.kt  VocabBlock.kt  ReadingBlock.kt  DialogueBlock.kt
    GrammarBlocks.kt  PhoneticsBlock.kt  WritingBlock.kt
    NotesQuizActions.kt    ← (ملاحظات/اختبار/إجراءات/إكمال — مشتركة)
  UniversalLessonScreen.kt ← LazyColumn فوق قائمة البلوكات (يستضيف الحوارات المشتركة)
  (الملفات الأربعة القديمة تُحذف بعد نقل أقسامها — لا نرمي تصميماً، ننقله)
```

> **قاعدة ذهبية #1:** أي كورس/مستوى مستقبلي = بيانات JSON فقط. إذا احتاج محتوى جديد فعلاً → نضيف «بلوكاً» واحداً يخدمه هو وغيره، لا شاشة.

### 🟢 المرحلة 4 — اختبار القبول الشامل (على الجهاز)
قائمة «جاهزية المستوى الأول» — **لا يُعلن الاستقرار إلا باجتيازها كاملة**:

1. استيراد حزمة المستوى الأول كاملة → رسالة نجاح واحدة لها بالأعداد الصحيحة.
2. فتح **كل** درس → كل محتواه ظاهر (كلمات/شرح/حوار/قراءة/صوتيات/كتابة).
3. إكمال درس → موافقة الكلمات → ظهورها في القاموس → دخولها جدول المراجعة.
4. اختبار درس (MCQ / صح-خطأ / audio_quiz) → نتيجة وتغذية راجعة صحيحة.
5. مراجعة يومية من شاشة المراجعة → تحديث الاستقرارية والاستحقاق.
6. **إغلاق وفتح التطبيق 3 مرات متتالية** → صفر فقدان، صفر اختفاء أقسام.
7. تصدير نسخة احتياطية → استيرادها → تطابق كامل (دروس، تقدم، كلمات، حالات FSRS).
8. فتح درس 25+ كلمة بدون تقطيع ملحوظ.
9. العدادات على لوحة القيادة/المستويات تطابق الواقع.

## 4) تجميد الميزات (حتى إكمال المستوى الأول) 🚫

لكي لا يتكرر «الهروب إلى التطوير»: **كل ما يلي مجمّد** حتى إشعار «أنهيت المستوى الأول»:

- ميزات جديدة من أي نوع (ألعاب، مكافآت، إحصائيات إضافية).
- تجميل زائد / إعادة تصميم شاشات عاملة (لوحة القيادة، المستويات، القاموس...).
- المزامنة السحابية وتحسينات `upload_tool`.
- أي «فكرة عابرة» أثناء الدراسة → تُكتب في قائمة في أسفل هذا الملف ولا تُنفذ.

**الاستثناء الوحيد:** خلل يكسر التعلم فعلياً (تعطّل، فقدان بيانات، محتوى لا يظهر) → يُصلح فوراً عبر نفس آلية البلوكات.

- مثال: توليد صوت تلقائي لمقاطع الاستماع عند الاستيراد.

## 5) مخاطر وشفافية
- **لا يوجد Android SDK في بيئة العمل هذه** → لا أستطيع تشغيل `gradle build` هنا. سأكتب التعديلات بدقة مع مراجعة صياغية صارمة، وخطوة الـBuild النهائية على جهازك (المرحلة 4 تشملها). أي خطأ ترجمة يظهر يُصلح خلال دقيقة.
